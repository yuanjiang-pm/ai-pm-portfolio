# 给 64M 小模型请一位"名师"：jiangyuan-minimodel 知识蒸馏实战

## 〇、一句话结论

**在 64M 学生已经 SFT 完成的前提下，用同代 MoE 大个头当白盒教师、用 45 万条数据做一轮 KL 蒸馏，可以让小模型的回答质量全面改善且零退化，成本不到 3 块钱。** 最重要的一个发现是：教师不是越大越好，而是"和学生越同代同分布，信号越干净"。

---

## 一、蒸馏的两种形态：先分清再动手

MiniMind 项目把蒸馏分成两类，这个框架值得先讲清楚：

| | 黑盒蒸馏 | 白盒蒸馏 |
|---|---|---|
| 学什么 | 只看老师的"答案"（硬标签） | 逐 token 拟合老师的**概率分布**（软标签） |
| 本质 | 对 teacher 输出做 SFT | CE + KL 混合损失：`L = α·CE + (1−α)·T²·KL(p_teacher ‖ p_student)` |
| 对教师的要求 | 只要会说话就行（Qwen3-4B 都行） | **必须和学生共用同一套词表 + 架构兼容** |
| 信息量 | 答案对了什么 | 在每个位置上，老师在候选词之间的相对倾向——"为什么这里放'下雨'而不是'降水'" |

本项目选择**白盒蒸馏**，这是预算约束下的理性选择：黑盒蒸馏需要大模型生成有规模的高质量数据，成本远超 4.5 元的预算；而白盒蒸馏只需要教师做前向传播，信号密度高得多。

对应实现是 MiniMind 仓库自带的 `trainer/train_distillation.py`：教师冻结、仅做 eval 模式前向传播，学生在真实标签损失（CE）和教师分布损失（KL）之间加权学习。

## 二、教师选型：一场"名师面试"

白盒蒸馏的第一硬约束是**同词表**（6400 词的 MiniMind tokenizer），这一条直接把 Qwen3、DeepSeek 这类通用大模型全部排除。于是把官方家族所有候选拉出来"面试"，逐个下载权重解剖结构：

| 候选 | 实测参数量 | 结构解剖结果 | 判定 |
|---|---|---|---|
| MiniMind2 dense | 108.95M | 768 维/16 层，GQA kv=2，intermediate 2048 | 可用，第一版方案 |
| minimind-3 dense | 68.8M | 768 维/8 层——**和学生同级** | ❌ 同龄人当不了老师 |
| **minimind-3-moe** | **203.3M 总参 / 64M 激活** | 4 专家 top-1，kv=4，intermediate 2432 | ✅ **最终录用** |

这里有个反直觉的要点：**教师的能力优势不体现在"损失绝对值低"，而体现在"师生分布差距小、信号可学"。** 数据说话——

- 用 MiniMind2（上一代 109M）当教师：蒸馏损失起点 **11+**
- 用 MiniMind-3-MoE（同代 198M-A64M）当教师：蒸馏损失起点 **0.63**

差了近 20 倍。原因：MiniMind-3-MoE 和学生是同一代训练管线（同一套数据配方、同一套 chat 模板）训出来的，它的分布就是"学生学了 30 遍还没学会的那份笔记"；而上一代教师虽然更大，但分布偏移大，KL 信号里混着大量"代际差异噪音"，学生学不过来。

另一个白送的便利：MiniMind-3-MoE 的专家层结构（kv_heads=4、intermediate=2432）与训练脚本的教师参数几乎一致，教师加载无需额外配置。

## 三、训练决策：三个"反直觉的保守"

1. **学习率砍到 SFT 的 1/10（5e-6）**。学生不是白纸，是已经 SFT 过的模型；蒸馏是在"名师点评"下微调，不是重学。lr 太大等于把已学知识冲掉重来，蒸馏就白做了。
2. **只跑 1 epoch**。45 万条数据、14063 步，教师分布信号是确定性目标（不像 SGD 噪声），多轮反而有过拟合教师分布的风险。
3. **α=0.5 平衡双损失**。CE 保证不丢硬标签能力，KL 提供软信号；实测全程 ce ~1.0-1.5、distill ~0.6-0.8，两条损失同步收敛，没有一边倒。

训练账单：RTX 3080 Ti 12GB，batch 32 刚好喂满（GPU 利用率 99%、显存 11.1GB），78 分钟跑完 14063 步，**GPU 费用约 2.3 元**。训练完成即刻关机止损。

## 四、效果验证：同一组问题，蒸馏前后

通过同一套 API 代理（OpenAI 规范，FastAPI + Ollama）问 6 个固定问题：

| 问题 | 蒸馏前 | 蒸馏后 |
|---|---|---|
| 下雨天要打伞吗 | ❌ "下雨天晴朗通常不会打伞""打伞时仍需谨慎"——自相矛盾 | ✅ 分情况判断 → 给行动建议 → 补充安全提示，逻辑通顺 |
| 1加1等于几 | ❌ "1加1=1+1=2（这个数是整数），结果是2" | ✅ "1 + 1 = 2" |
| 秋天的诗 | 四句短诗，工整但平 | 散文诗，有比喻有情绪推进 |
| 解释机器学习 | 啰嗦、概念边界糊 | "从数据中学习并改进性能"，准确简洁 |
| 你是谁 ×2 | 固定话术 ✓ | 固定话术 ✓（**零退化**） |

两个值得单独说的点：

- **"1+1=2"这个案例的含金量**：小模型答错的从来不是知识（它"知道"答案），而是输出的简洁性和稳定性——这正是教师分布信号最擅长修的东西：KL 让学生在高置信位置收窄分布，输出就不再绕圈。
- **身份话术零影响是架构红利**：模型身份由 API 代理层正则拦截（此前的工程决策：身份与权重解耦），蒸馏只动权重，所以"我是由 jiangyuan 训练的高效助手"一字不变。**模型的归模型，服务的归服务**，这个分层在这次验证了价值。

### 4.1 能力边界：10 题系统性评测

蒸馏解决的是"分布稳定"问题（蒸馏前模型经常完全跑题、模式坍缩），不改变参数量决定的能力上限。10 题分类评测（事实/数学/推理/常识/写作/翻译/指令跟随，走真实部署链路）给出的定量画像：

- **偏科显著**：开放生成类（常识解释、写作）方向正确率约 2/3；精确任务类（算术、翻译、事实回忆、逻辑推理）接近 0
- **采样方差大**：temperature 0.7 下同一道事实题三次采样可以横跨"完全正确→完全跑题"
- **工程含义**：适合当聊天、头脑风暴、文本润色的陪跑模型；当问答引擎会稳定翻车。剩余错误是 64M 参数的物理上限，不是蒸馏质量或训练轮次能解决的

**"蒸馏前经常完全跑题" → "蒸馏后多数问题方向正确"，这一步是分布层面的修复；而绝对分数的天花板，由参数量决定。** 两件事分开看，才知道钱花在哪有效、花在哪无效。

## 五、沉淀：四条普适判断

1. **选教师，同代同分布 > 绝对参数量。** 蒸馏损失 0.63 vs 11+ 的差距说明：一份学生看得懂的笔记，胜过一本更好的天书。判据可以直接用"冒烟 100 步的 distill loss 量级"来验证。
2. **蒸馏是微调不是重训。** 继承权重 + 十分之一学习率 + 单轮数据，保守的三个决策共同保证了"只变好不变坏"。
3. **预算约束下的资源次序：数据 > 教师 > 时长。** 有限预算迫使把钱花在刀刃上——45 万条数据（信号密度）比多跑几轮（重复看同样的信号）值钱得多。
4. **学生-代理分层的工程价值在模型升级日兑现。** 换权重不动服务，客户端零感知——这是当初修复多客户端适配问题时埋下的种子。
