# D9：模型评估与量化

## 📖 今日主题

怎么知道模型到底行不行？——从评估指标到模型瘦身的全链路

---

## 概念讲解

### BLEU（Bilingual Evaluation Understudy）

**核心思想**：衡量生成文本和参考文本的n-gram重叠程度——说白了，就是"你说的和我期待的有多少词组一样"。

**计算逻辑**：

1. 统计生成文本中每个n-gram在参考文本中出现的次数（取截断计数，防止重复生成刷分）
2. 计算各阶n-gram的精度（1-gram到4-gram）
3. 几何平均
4. 乘以**长度惩罚（Brevity Penalty）**，防止生成超短文本刷高精度

```
BLEU = BP × exp(Σ wn × log pn)

其中：
- pn = n-gram精度
- wn = 权重（通常均分）
- BP = brevity penalty
  BP = 1                  (生成长度 > 参考长度)
  BP = exp(1 - 参考长度/生成长度)  (否则)
```

**关键理解**：BLEU是**精度导向**——"我生成的里面有多少是对的"，但不关心"参考的里面有多少被我覆盖了"。

---

### ROUGE（Recall-Oriented Understudy for Gisting Evaluation）

**核心思想**：和BLEU镜像对称——衡量参考文本中有多少内容被生成文本覆盖了。**召回导向**。

**主要变体**：

- **ROUGE-N**：基于n-gram的召回率，计算参考文本的n-gram有多少出现在生成文本中
- **ROUGE-L**：基于最长公共子序列（LCS），允许非连续匹配，更灵活
- **ROUGE-S**：跳元组（Skip-bigram），允许中间跳过词

```
ROUGE-N = 参考文本n-gram被覆盖数 / 参考文本n-gram总数

ROUGE-L = LCS长度 / 参考文本长度
```

**关键理解**：ROUGE问的是"该说的我有没有说到"，BLEU问的是"我说的有多少是对的"。一个偏召回，一个偏精度。

---

### 困惑度（Perplexity）

**核心思想**：模型对文本的"困惑程度"——模型越不困惑（越能预测），说明理解越深。

**数学本质**：测试集上每个token的平均负对数似然的指数

```
PPL = exp(-1/N × Σ log P(wi | w1,...,wi-1))

PPL越低 → 模型预测越准 → 模型越好
```

**类比**：想象模型在猜下一个词，如果每次都很确信（概率高），困惑度就低；如果每次都很纠结（概率分散），困惑度就高。一个完美的模型PPL=1（完全确定），随机猜测PPL=词表大小。

**使用场景**：评估语言模型本身质量，不需要参考文本，直接用模型对文本的预测概率计算。

---

### 模型量化（Quantization）

**核心思想**：用更少的位数表示模型参数，牺牲一点点精度换大幅的推理加速和内存节省。

**精度层级**：

```
FP32（32位浮点）→ FP16（16位浮点）→ INT8（8位整数）→ INT4（4位整数）
  精度最高          精度高、速度翻倍     精度可接受、速度4x    极致压缩、精度损失大
  内存基准          内存减半            内存1/4              内存1/8
```

**两种量化策略**：

|  | Post-training Quantization (PTQ) | Quantization-aware Training (QAT) |
|-|-|-|
| **时机** | 模型训练完后量化 | 训练过程中模拟量化 |
| **做法** | 直接截断/映射参数 | 前向传播插入量化/反量化节点 |
| **精度损失** | 较大（尤其INT4） | 较小（模型已适应量化误差） |
| **成本** | 低，无需重训 | 高，需要额外训练 |
| **适用** | FP16或INT8量化 | 需要更低比特（INT4）时 |

**类比**：PTQ像是把高清照片直接压缩成JPEG，画质会有损失；QAT像是摄影师就知道要压缩，拍摄时就考虑了压缩后的效果，所以压缩后看着更好。

---

## 关键对比

| 指标 | 方向 | 核心计算 | 典型用途 | 局限 |
|-|-|-|-|-|
| BLEU | 精度 | n-gram匹配+长度惩罚 | 机器翻译 | 不衡量语义理解 |
| ROUGE | 召回 | n-gram/LCS覆盖 | 文本摘要 | 不衡量生成质量 |
| Perplexity | 预测能力 | 平均负对数似然 | 语言模型评估 | 只衡量流畅性，不衡量正确性 |

| 量化方式 | 训练后量化(PTQ) | 量化感知训练(QAT) |
|-|-|-|
| 核心区别 | 事后压缩 | 训练时适应 |
| 精度保持 | 一般 | 更好 |
| 实施成本 | 低 | 高 |

## 🕯️ 易错陷阱

> **⚠️ 坑点1：BLEU高 ≠ 理解能力强**
> 
> BLEU只衡量"表面相似度"——词组重合度。一个模型可以BLEU很高但完全不理解语义。比如调换语序可能BLEU骤降但语义不变，或者同义替换BLEU很低但语义完美。

> **⚠️ 坑点2：ROUGE侧重召回，BLEU侧重精度**
> 
> 考试最常考的区分点。记住：R-O-U-G-E = Recall-Oriented，名字就告诉你了。摘要任务关心"有没有遗漏重要信息"，所以用ROUGE；翻译任务关心"翻译出来的词准不准"，所以用BLEU。

> **⚠️ 坑点3：Perplexity越低越好，但低不代表回答正确**
> 
> PPL低说明模型预测下一个token很"确信"，但确信不代表对。模型可能对错误答案也很确信。

> **⚠️ 坑点4：PTQ和QAT的选择不是"哪个更好"**
> 
> 如果只是FP16量化，PTQ几乎无损失，没必要QAT。需要更激进压缩（INT4）时QAT才有明显优势。选择取决于目标比特数和可接受的精度损失。

## 练习题

### Q1: 评估一个文本摘要系统，以下哪个指标最合适？

A) BLEU  
B) ROUGE  
C) Perplexity  
D) 准确率

**答案：B**  
**解析**：摘要评估的核心是"重要信息有没有被覆盖"——这是召回导向的问题，ROUGE正是Recall-Oriented。BLEU侧重精度，更适合翻译任务。

---

### Q2: 关于模型量化，以下说法正确的是？

A) PTQ一定比QAT精度低  
B) FP16量化通常需要QAT才能保持精度  
C) 量化感知训练在训练过程中模拟量化误差，使模型适应低精度表示  
D) INT8量化后模型大小变为原来的1/8

**答案：C**  
**解析**：A错误——PTQ在FP16或INT8时精度损失很小，不一定比QAT差。B错误——FP16的PTQ几乎无损失。C正确——QAT的核心就是在训练时插入量化/反量化节点，让模型学会适应量化误差。D错误——INT8是32位的1/4，不是1/8。

---

### Q3: BLEU的Brevity Penalty（长度惩罚）的作用是什么？

A) 奖励更长的生成文本  
B) 惩罚生成文本比参考文本短的情况，防止通过生成超短文本刷高精度  
C) 确保生成文本和参考文本长度完全一致  
D) 提高n-gram的匹配精度

**答案：B**  
**解析**：如果没有BP，模型只输出一个完全正确的短句就能得到极高的n-gram精度。BP通过惩罚过短的输出来防止这种"作弊"行为。当生成长度≥参考长度时BP=1（不惩罚），否则BP<1（惩罚）。
